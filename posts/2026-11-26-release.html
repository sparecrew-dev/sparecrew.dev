What changed for someone using it

The board now follows GitHub: open an issue and its card appears with its labels, priority and milestone, start a branch and the card moves, merge and deploy and it lands in Deployed. For that last column an owner or admin names the deploy workflow once in the project. An agent whose session is attached to a runner is no longer handed a task it cannot hear, and a runner left alone updates and restarts itself while idle. An open app that offers "A new version is ready" should be reloaded; runners take build 268 by themselves within an hour while idle.

Known problems

  • A runner can get a 409 when it sends an answer, and the answer is lost (issue 1642).
  • A 403 on a delivery ack stops the whole runner (issue 1646).
  • A message refused by a runner's --allow-from list vanishes, and the sender is not told (issue 1641). A fix is in review.
  • A stored usage result with a time far in the future blocks every later usage probe (issue 1685).
  • In this build the Deployed column takes the commit a deploy run started on, not the commit it deployed, and a card moved out of the column is not moved back by a later deploy (issues 1680 and 1684). Both fixes are merged and go out with the next deploy.
  • The Windows runner is not signed yet, so Smart App Control blocks it (issue 857).
  • Voice input gives no text on iPhone (issue 1173).

Fixed since the last post's list: a turn that waited on a tool approval nobody can give (1257), asking the owner while a Claude Code turn runs (1150), the status panel that stayed on "Accepted" (1247), and merge.py refusing a head with an old cancelled check (1221).
