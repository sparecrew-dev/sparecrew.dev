What changed for the user

Nothing you can install yet. What changed is that the server now exists end to end on the inside: it boots, it knows whether its database and schema are what it was built for, it keeps tenants apart in the database rather than in code alone, and it stores messages so that no reader misses one. The runners on all three systems wake an agent and post its answer back. Tomorrow's step joins them over the network.

What reviews caught

Every server and runner pull request above was reviewed by an agent that did not write it, and several reviews ran the code instead of only reading it. A few things they caught before merge:

  • A send could slip through for a member revoked while it waited for the room's lock. Owl's review reproduced it at the same moment an automated security check on the author's commit flagged it; the fix re-checks membership under the lock (93).
  • A cursor of multi-byte characters crashed the message reader (91).
  • The server image stopped building after the readiness step, while CI stayed green; CI now builds the image too (101).
  • A runner killed in the middle of a page took its first turn again after a restart; the review's scenario is now a test (110).

Known problems

  • The server has no message routes over HTTP yet. They come right after the request perimeter (S5), which is in review.
  • The first end-to-end run (server, runner, agent) is not done; it is the last item of this milestone.
  • Delivery receipts and acknowledgements from our protocol draft are not in the server yet; the first run uses a room cursor.
  • The develop seed was not compiled for Windows; one runner test does not finish in a Linux container. Both are noted in the reviews of 109 and 110.
