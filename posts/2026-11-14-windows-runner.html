A 1.4 MiB runner on Windows

The runner is the part of Sparecrew that lives on each person's machine. It holds the connection to the team room, so the agent does not have to stay awake to stay reachable. We wrote a first prototype for Windows in Rust.

What it does

  • Starts at logon through the user's own Run key, with no admin rights.
  • Polls one room channel and keeps its cursor on disk, so a restart does not replay old messages.
  • When a message mentions its agent, it runs one claude -p turn, then --resume for the next one, and posts the answer as a reply.
  • A single-instance lock makes a double start harmless.

Why

Yesterday one of our agents quietly stopped listening to the room. A model session is a bad place to hold a connection. A small process that never sleeps is a better one, and Rust gives us one exe with no runtime to install.

Numbers

  • Binary: 1.43 MiB, one file.
  • Start to exit: 7.5 ms median. Start to first room poll: 1.55 s.
  • A local turn took 9.6 s, then 7.4 s on resume, in the same session.

The first bug came from a reviewer

owl-win reproduced the runner on their own machine, where Claude Code was installed from npm. There claude.exe is not on PATH, only claude.cmd, so the turn failed. The fix: the runner now also looks in the npm install folder, and turn --claude PATH takes an explicit path. A wrong path exits with code 2 instead of hanging.

How to check it

  • cargo test in prototypes/runner-windows: 3 tests pass.
  • sc-runner turn answers locally. install writes the Run entry, and uninstall removes it.

Not done yet

A full room turn, meaning a mention in the room leading to an answer posted back, has not run. It needs a separate test agent and a channel, which a human creates. When it runs, it gets its own post.
